# Verification Tests

These are workflow verification tests generated by the `verify-workflow` pipeline. They cover two rounds
of verification against a real, running `trayline-server` backend — no mocked API calls or agent
responses:

1. **Attach/OCR flow** (`workflow-assistant-*`, `workflow-project-agent-*`, `workflow-login-token`) — the
   attach-a-file-and-get-an-AI-description-or-OCR flow (📎 file picker, drag-and-drop, copy-paste) for
   both the project agent (`/[project]/agent`) and the main/assistant agent (`/assistant`).
2. **Mobile/responsive UX** (`workflow-mobile-*`, `workflow-tablet-desktop-responsive`) — every page
   rendering correctly at 375px (mobile), 768px (tablet), and 1280px (desktop): no horizontal overflow,
   readable/tappable controls, and the hamburger menu opening, toggling closed, and closing automatically
   on navigation.

## Running

The application must be running locally first:

```bash
PUBLIC_API_URL=http://trayline-server:9000 npm run dev -- --host 0.0.0.0 --port 5173
```

Then, from `dashboard/`:

```bash
npx playwright test e2e/verification/
```

Agent replies stream from a real LLM in a spawned container, so individual tests can take up to ~120s.

## Ad-hoc image testing

`adhoc-user-image.spec.ts` is a general-purpose helper, separate from the `workflow-*.spec.ts` tests
above. Instead of asserting on a specific fixture's known content, it attaches whatever image path you
give it to a fresh `/assistant` session, asks the agent to describe it, and prints the full reply to the
console — useful for quickly checking a real, arbitrary image (not just the small test fixtures) without
writing a one-off test. Point it at an image with `ADHOC_IMAGE_PATH` (defaults to
`/workspace/.agents/tmp/data/samsung-photo1.jpg`):

```bash
ADHOC_IMAGE_PATH=/path/to/your-image.jpg npx playwright test e2e/verification/adhoc-user-image.spec.ts --reporter=list
```
